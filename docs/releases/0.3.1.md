# Android 0.3.1：会话状态与历史浏览修复

日期：2026-09-09

## 修复范围

- [x] 会话列表统一订阅本地快照，网络只写缓存，不再直接替换界面列表。
- [x] 本地发送队列参与摘要和排序；显示发送中、失败，重试和发送回执可实时更新。
- [x] 本地预览时间不覆盖服务器消息 ID/时间，不增加未读数；确认消息到达后移除重复预览。
- [x] 请求前记录会话版本，保护请求期间更新的消息、已读、静音和删除状态；已读位置只前进。
- [x] 列表支持加载更多及独立重试，排序后仍保留稳定会话标识；在顶部时显示移到首位的活跃会话，浏览下方时不强制回顶。
- [x] 历史消息改为订阅已展开的 ID 范围，收到新消息、编辑或删除时不退回最新 50 条；加载旧缓存不依赖网络。
- [x] 草稿正文和富文本实体持久化，并显示列表草稿提示；编辑已有消息不覆盖原草稿。

“上移”指按最新活动时间重新排序，不是新增协议中的置顶功能。服务器最新消息、客户端待发送预览、草稿分开保存；草稿提示不改变未读数，也不把服务器排序时间改成本地时间。

## 数据与生命周期

Room 10 → 11 新增 `drafts` 表，保留既有消息、队列和账号信息。草稿输入防抖 300 ms 保存，页面退出和应用切入后台时补保存；进程被强制终止前不足 300 ms 的最后输入仍可能没有落盘。同步重建保留草稿，清理账号缓存时一并清除。草稿不跨设备同步。

服务端会话分页仍使用现有 `before_time` 游标，不引入新协议。分页不是服务端快照；期间新消息继续通过同步更新本地列表。历史窗口随浏览范围扩展，不通过无限增大默认查询上限来隐藏分页问题。

## 验收

1. 从列表下方打开会话发送消息，返回列表，确认摘要和顺序立即更新；断网时检查发送中/失败提示。
2. 重试并恢复网络，确认消息不重复，且旧请求完成后摘要、时间、已读状态不回退。
3. 超过 50 个会话时加载下一页；加载失败时在列表底部重试，不丢失已显示内容。
4. 上滑展开超过 50 条历史，再接收新消息、编辑或删除，确认历史仍在；搜索结果定位后也保持可见范围。
5. 输入含提及的草稿后返回列表，再重启应用，检查正文与提及 ID 保留；编辑旧消息后原草稿仍可恢复。
6. 覆盖升级保留已登录账号及数据；自动化设备测试使用独立模拟器，避免清理体验设备。

自动化覆盖持续 Flow 订阅下的发送/失败/重试/回执/删除、列表排序、陈旧快照、已读单调性、历史窗口、草稿重启/账号清理、数据库迁移和 Compose 列表状态/加载更多交互。

本地验收结果：105 项 JVM 测试、独立 API 36 模拟器上的 25 项设备测试通过；Debug APK、Release Bundle 和 Debug Lint 通过。体验模拟器覆盖升级至 0.3.1 后保留登录与数据。在 dev 环境向现有 AgentRoot 发送只读 `/myagents` 命令，确认会话由第六位移到第一位、回复更新摘要、进入聊天清除未读，以及刷新后状态保持。断网失败与重试由自动化状态测试覆盖，未在体验设备切断网络。
